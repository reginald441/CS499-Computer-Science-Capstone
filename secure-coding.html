Project overview

Learning to treat security as part of development, not an afterthought.

CS 405 strengthened my understanding of how software vulnerabilities can begin with small coding decisions and grow into larger security problems if they are not identified early.

Across the course, I worked with numeric overflow and underflow, SQL injection, secure coding standards, exception handling, unit testing, encryption, static code analysis, and security policy development. The work moved from identifying individual weaknesses to thinking about security as a repeatable process that includes prevention, testing, analysis, documentation, and continuous improvement.

The final project brought these ideas together in a Green Pace security policy presentation. I used the course work to explain coding standards, encryption strategy, the Triple-A framework, unit testing, DevSecOps automation, risk assessment, and recommendations for maintaining secure software development practices.

Development work

Key secure coding practices

The completed work demonstrates practical security techniques across code, testing, analysis, and policy.

Numeric safety

Examined integer overflow and underflow and applied validation techniques to reduce arithmetic errors and unsafe behavior.

SQL injection prevention

Reviewed injection risks and strengthened input handling and safer programming practices to reduce the chance of malicious database input.

Exception handling

Used structured exception handling to manage errors, propagate failures correctly, and avoid unsafe or uncontrolled program termination.

Automated unit testing

Used Google Test to create repeatable tests that verify expected behavior and help detect defects before software is released.

Encryption and data protection

Applied encryption concepts to data in flight, at rest, and in use, connecting technical controls to broader security policy decisions.

Static code analysis

Used Cppcheck and external testing methods to identify potential vulnerabilities and evaluate code before deployment.

Course outcome evidence

Risk awareness, testing, policy, and defense in depth.

This project demonstrates my ability to evaluate software from a security perspective and connect individual coding decisions to larger organizational risk.

I learned that secure software depends on layers of protection. Input validation, safe numeric operations, controlled error handling, encryption, authentication and authorization, testing, static analysis, and monitoring each address different parts of the problem. When these controls are used together, one weakness is less likely to become a complete system failure.

The policy and presentation work also strengthened my ability to communicate security requirements clearly. Instead of only fixing code, I had to explain why a control was needed, when it should be applied, how it could be tested, and what risk remained if the organization decided to delay mitigation.

Security principle applied: Defense in depth reduces dependence on any single control. Secure design, coding standards, testing, encryption, access control, logging, and monitoring work together to prevent, detect, and limit the impact of vulnerabilities.
