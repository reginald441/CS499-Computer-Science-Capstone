Project overview

From frequency counting to deeper algorithmic analysis.

Corner Grocer processes grocery purchase records, counts how often items appear, supports item searches, and produces frequency-based reports and histograms.

I selected this artifact because the original application already solved a clear real-world problem while giving me an opportunity to demonstrate how the choice of a data structure changes the way a program stores, searches, and reports information.

The original version emphasized file input/output, classes, functions, and straightforward frequency counting. For the capstone, I expanded the project so the enhancement would show more than functional C++ code. The revised work focuses on algorithmic design decisions, balancing, searching, reporting, complexity, and measurable trade-offs between approaches.

Enhancement work

Key algorithms and data-structure improvements

The enhancement was designed to demonstrate both implementation skill and the reasoning behind selecting and evaluating a data structure.

Self-balancing red-black tree

Replaced a simpler map-centered approach with a custom red-black tree using sentinel nodes, left and right rotations, color balancing, and tree invariants.

Efficient searching

Organized item-frequency records so searches can follow the tree structure instead of relying on a purely sequential scan.

Normalized item handling

Improved consistency for item searching and comparisons by normalizing strings before lookup and reporting.

Flexible reporting

Expanded the output beyond a single report style and used secondary ordering where appropriate for readable frequency-based results.

Complexity trade-offs

Compared runtime, memory, scaling behavior, and Big-O implications so the enhancement explains why the chosen structure is appropriate instead of only showing that it works.

Testing and benchmarking

Used tests and empirical performance comparisons to evaluate correctness, balancing behavior, searching, sorting, and reporting under different workloads.

What I learned

Choosing a structure is an engineering decision.

This enhancement strengthened my understanding that a working solution and a well-evaluated solution are not always the same thing.

Implementing the red-black tree required careful handling of node relationships, rotations, coloring rules, and edge cases. It also made the trade-off between using a standard library abstraction and implementing a lower-level structure much more visible.

The project helped me connect theoretical complexity to practical behavior. I learned to explain how search, insertion, ordering, memory use, and scalability affect design choices and to support those explanations with both Big-O reasoning and measured results.

Course outcome connection: The artifact demonstrates the design and evaluation of computing solutions using algorithmic principles while managing trade-offs involved in data-structure and software-design choices.
