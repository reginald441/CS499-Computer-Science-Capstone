Project overview

Connecting the frontend, backend, API, and database into one application.

Travlr Getaways is a full-stack travel application with a traditional customer-facing website and an Angular single-page application for administrators.

The project brought together frontend development, backend routing, RESTful API design, MongoDB persistence, reusable Angular components, services, JSON data exchange, and authentication. Building the application helped me understand how each layer has a separate responsibility while still depending on clear communication with the others.

The customer-facing portion used Express and HTML templates, while the administrative SPA provided a more dynamic interface without requiring a full page reload for every action. MongoDB stored trip data as flexible documents that aligned naturally with the JSON data exchanged by the API.

Development work

Key full-stack improvements

The completed application demonstrates how multiple web technologies can work together as one maintainable system.

Angular administrative SPA

Built reusable Angular components and services so administrative trip management remains organized and easier to maintain.

RESTful API integration

Connected frontend requests to backend endpoints using GET, POST, PUT, and DELETE operations for application data.

MongoDB data layer

Stored and retrieved flexible travel documents through a NoSQL database that maps naturally to JSON-based application data.

Reusable components

Reduced repeated interface logic by centralizing common display and data-access responsibilities in components and services.

Authentication and security

Protected administrative functionality so sensitive operations require valid authentication instead of relying on the frontend alone.

Layered troubleshooting

Tested the frontend, routes, API, database, and authentication flow to isolate problems across the full application stack.

Course outcome evidence

Architecture, integration, maintainability, and security.

This project demonstrates my ability to build and reason about a complete web application rather than treating frontend, backend, database, and security as unrelated topics.

I learned how structured data moves between interfaces and APIs, why reusable components improve maintainability, and why protected operations must be enforced on the backend. The project strengthened my ability to trace errors across multiple layers and to make technical decisions based on how the entire system works together.

Trade-off considered: Separating the application into multiple layers adds setup and coordination, but the separation makes each responsibility clearer and allows the frontend, API, and database logic to evolve more independently.
