Project overview

Connecting software logic to real-world hardware.

The CS-350 coursework progressed from basic GPIO and LED control into a complete thermostat project that responds to physical inputs and environmental data.

I worked with GPIO interfaces, buttons, serial communication, an LCD display, temperature and humidity sensing, and state-machine programming. The final thermostat work brought these pieces together so the software could read environmental information, respond to button input, manage thermostat states, and communicate with a thermostat server simulator.

This project gave me practical experience with the challenges of embedded development, where correct software also depends on correct wiring, pin assignments, device communication, timing, and hardware behavior.

Course progression

From individual components to an integrated system

I built and tested the system in smaller pieces before combining them, which made troubleshooting more manageable and helped isolate hardware and software problems.

GPIO & LED control

Used Python and Raspberry Pi GPIO interfaces to control outputs and understand basic hardware interaction.

Serial communication

Worked with client/server serial communication to send and receive information between system components.

LCD display

Integrated an LCD display so the embedded system could present information directly to the user.

Buttons & state machines

Used physical button input and state-machine logic to organize system behavior and transitions.

Environmental sensing

Tested and integrated temperature and humidity readings from the AHTx0 sensor.

Thermostat integration

Combined sensing, user input, state logic, display behavior, and server simulation in the final thermostat work.

What I learned

Testing each layer matters in embedded development.

One of the most important lessons from this project was learning to troubleshoot systematically instead of assuming every problem was caused by the code.

I tested components separately before integrating them into the larger system. This made it easier to determine whether a problem came from software logic, GPIO configuration, wiring, pin assignments, communication, or a hardware component. State-machine design also gave me a clearer way to organize behavior that changes in response to inputs and conditions.

Engineering lesson: In an embedded system, software and hardware have to be treated as one system. A small wiring, configuration, or state-transition mistake can change the behavior of the entire application.

Transferable skills

Skills that extend beyond one thermostat.

The project strengthened my ability to design reactive systems, integrate hardware and software, read technical documentation, test components independently, and troubleshoot problems methodically.

These skills transfer to Internet of Things devices, automation systems, robotics, industrial controls, sensor-based applications, and other environments where software must interact reliably with physical devices and changing real-world conditions.
