Professional Self-Assessment

Growth from writing code to making engineering decisions.

Completing the computer science program and building this ePortfolio helped me see my work as more than a collection of assignments. I have learned to approach software as a complete system that must solve a real problem, communicate value to its users, protect information, remain maintainable, and make responsible use of technical resources.

My coursework strengthened my ability to collaborate and communicate in technical environments. Through discussions, project planning, documentation, code reviews, testing notes, and written explanations, I learned that a strong technical solution is not enough by itself. Developers must be able to explain requirements, justify design choices, respond to feedback, document their work, and communicate with both technical and nontechnical audiences. The informal code review in this portfolio is one example of that growth because I had to examine an existing application, identify weaknesses, and explain a realistic enhancement plan before changing the code.

The three capstone artifacts show different parts of my development as a computer science professional. The Android Inventory Tracker demonstrates software design and engineering through architectural separation, stronger authentication, validation, user-specific data, testing, and maintainability. Corner Grocer demonstrates algorithms and data structures through a custom self-balancing red-black tree, searching, reporting, complexity analysis, and evaluation of runtime and memory trade-offs. The Grazioso Salvare Dashboard demonstrates database development through MongoDB indexing, query optimization, controlled CRUD operations, validation, error handling, and defensive data-access practices.

Security became a consideration across the entire development process rather than something added after an application was complete. Password hashing, input validation, user-specific records, controlled query construction, and attention to NoSQL injection risk helped me understand that software design decisions can directly affect privacy and data protection. I also learned that performance and security decisions involve trade-offs. An index can improve frequent database queries while increasing storage and write costs, and a custom data structure can provide valuable control and learning while also adding implementation complexity that must be tested carefully.

These experiences strengthened my skills in Java, C++, Python, Android development, SQLite, MongoDB, software architecture, algorithms, data structures, testing, documentation, and secure programming. More importantly, they improved how I evaluate problems. I now think more deliberately about who will use a system, how the data should move through it, what can fail, what could be exploited, how the solution will perform as it grows, and how another developer could understand and maintain the work later.

As I move forward professionally, I want to continue building software that connects strong engineering practices with practical value. This portfolio represents my ability to take earlier work, evaluate it critically, respond to feedback, and improve it with clearer architecture, stronger algorithms, better database practices, and a security-focused mindset. Together, the artifacts show the progress I have made and the foundation I will continue building on throughout my career.
